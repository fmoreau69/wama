Jusqu'au 2026-09-22 ce bloc vivait dans `home.html` seul : l'avatar disparaissait dès qu'on quittait l'accueil, et « affiché / masqué » n'était qu'un état de page (`WAMA_VOLETS.md §5`, §8 n°5). UN accordéon (Fabien, 22/09 : « tout ce qui est lié à l'assistant dans le volet droit doit être contenu dans l'accordéon pour pouvoir se replier d'un coup ») : l'avatar (`#assistant-avatar`, rendu par `wama-avatar.js`) et, hors accueil, le MINI-CHAT (`#assistant-chat`, `wama-assistant-chat.js`) — même fil que l'accueil, voix commune (`wama-assistant-voice.js`), réglages de l'accueil (modèle, curseur, voix choisie) inchangés et durables : le volet ne montre qu'un rappel en lecture seule du dernier tour. Sur l'accueil, le chat complet est déjà là : le partial ne rend que l'avatar (`assistant_avatar.compact_chat`). Ce qui persiste est la PRÉFÉRENCE (brique `user_settings`, app `assistant`, clés `avatar` — activé par défaut —, `avatar_collapsed` — l'accordéon —, `voice`), lue sur chaque page par le context processor `assistant_avatar` et rendue ici en `data-*`. Le comportement (chargement à la demande, repli, bascule) est dans `wama-avatar-panel.js`, chargée par `base.html`. ⚠ Rendu même quand la préférence est désactivée (`data-enabled="0"`, masqué) : la page d'accueil peut ainsi réactiver l'avatar SANS rechargement. Cela ne coûte rien — le module three.js/TalkingHead (~6 Mo) n'est importé qu'au moment où l'avatar doit être VISIBLE. ⚠ En mode SIMPLIFIÉ le volet droit entier est masqué (`body.wama-simple`) : l'avatar n'y existe pas, et la brique ne charge rien tant que ce mode est actif. {% endcomment %}
